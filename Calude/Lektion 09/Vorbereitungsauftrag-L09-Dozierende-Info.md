# Vorbereitungsauftrag Lektion 9 - Dozierende Info

## Übersicht für Dozierende

Diese Datei enthält 8 verschiedene Optionen für Vorbereitungsaufträge zu Lektion 9 (KI & Datenbanken), plus Quick-Aufgaben für Studierende mit weniger Zeit.

### Zweck des Vorbereitungsauftrags

**Ziele:**
1. Studierende sammeln erste Erfahrungen mit KI-Tools
2. Hands-on Ausprobieren vor der theoretischen Lektion
3. Eigene Meinung zu KI bilden (nicht durch Dozierende vorgegeben)
4. Basis für Diskussion in Lektion 9 schaffen

**Zeitaufwand:** 20-60 Minuten (je nach gewählter Option)

---

## Empfohlene Vorgehensweise

### Variante A: Freie Wahl (Empfohlen)
- Studierende wählen selbst 1-2 Optionen
- Fördert intrinsische Motivation
- Unterschiedliche Erfahrungen für Diskussion

### Variante B: Pflicht-Option
- Alle machen Option 1 (Tool Exploration)
- Einheitliche Basis für Diskussion
- Einfacher auszuwerten

### Variante C: Gruppen-Arbeit
- Gruppen à 2-3 Personen
- Jede Gruppe testet eine andere Option
- Präsentation der Ergebnisse zu Beginn von L09

## Die 8 Optionen im Detail

### Option 1: KI-Tool Exploration ⭐ EMPFOHLEN
**Zeitaufwand:** 30 Min.
**Schwierigkeit:** Einfach
**Gut für:** Alle, Einstieg in KI-Tools

**Was Studierende lernen:**
- Verschiedene KI-Tools kennen
- Grundlegendes Prompting
- Kritisches Denken (Antworten bewerten)

**Dozierende können erwarten:**
- Verschiedene Tools wurden getestet
- Erste Meinungen zu Nützlichkeit
- Konkrete Beispiele für Diskussion

**Bewertung:**
- Wurden mindestens 3 Aufgaben getestet? ✓
- Sind die Antworten dokumentiert? ✓
- Wurde kritisch reflektiert? ✓

---

### Option 2: Eigene Datenbank optimieren
**Zeitaufwand:** 45 Min.
**Schwierigkeit:** Mittel
**Gut für:** Studierende mit bestehendem Projekt

**Was Studierende lernen:**
- Praktische Anwendung auf eigenen Code
- Query-Optimierung
- Kritische Bewertung von KI-Vorschlägen

**Dozierende können erwarten:**
- Konkreter Vorher/Nachher Vergleich
- Messbare Verbesserungen (oder deren Fehlen)
- Reflexion über Umsetzbarkeit

**Bewertung:**
- Wurde eigener Code verwendet? ✓
- Sind Verbesserungen dokumentiert? ✓
- Wurde kritisch bewertet? ✓

---

### Option 3: KI-Prompting üben
**Zeitaufwand:** 20 Min.
**Schwierigkeit:** Einfach
**Gut für:** Verständnis für Prompt-Qualität

**Was Studierende lernen:**
- Wie Prompt-Qualität Antwort-Qualität beeinflusst
- Konkrete Verbesserungen in Prompts
- Strukturiertes Prompting

**Dozierende können erwarten:**
- Mindestens 3 verschiedene Prompt-Qualitäten
- Sichtbare Unterschiede in Ergebnissen
- Verständnis für "gutes Prompting"

**Bewertung:**
- Wurden unterschiedliche Prompts getestet? ✓
- Ist der Unterschied erkennbar? ✓
- Wurde daraus gelernt? ✓

---

### Option 4: KI vs. Dokumentation
**Zeitaufwand:** 30 Min.
**Schwierigkeit:** Mittel
**Gut für:** Kritisches Denken, Quellenvergleich

**Was Studierende lernen:**
- Stärken/Schwächen verschiedener Quellen
- Wann welche Quelle nutzen
- Kritische Bewertung von KI-Antworten

**Dozierende können erwarten:**
- Strukturierter Vergleich
- Vor-/Nachteile identifiziert
- Begründete Präferenz

**Bewertung:**
- Wurden mindestens 3 Quellen verglichen? ✓
- Ist der Vergleich fair? ✓
- Gibt es eine begründete Schlussfolgerung? ✓

---

### Option 5: Prompt Engineering Challenge
**Zeitaufwand:** 45 Min.
**Schwierigkeit:** Schwer
**Gut für:** Fortgeschrittene, die sich fordern wollen

- Iteration und Verbesserung

**Dozierende können erwarten:**
- Ambitionierte Prompts
- Code der getestet wurde
- Ehrliche Reflexion über Erfolg/Misserfolg

**Bewertung:**
- Wurde mindestens 1 Challenge versucht? ✓
- Wurde der Code getestet? ✓
- Wurde reflektiert was nicht funktioniert hat? ✓

### Option 6: KI-Kritik üben

## Häufige Probleme & Lösungen

### Problem 1: "Ich habe keinen Zugang zu KI-Tools"
**Lösung:**
- ChatGPT Free Version reicht vollständig
- Claude.ai hat kostenlose Version
- Perplexity.ai ist ohne Login nutzbar
- Notfalls: Option 4 nur mit Docs/Stack Overflow

### Problem 2: "Die KI gibt mir keine guten Antworten"
**Lösung:**
- Das ist Teil der Lernerfahrung!
- Dokumentieren was nicht funktioniert hat
- Genau DAS in Lektion 9 besprechen

### Problem 3: "Ich weiß nicht welche Option ich wählen soll"
**Lösung:**
- Option 1 ist der sichere Einstieg
- Quick-Aufgaben wenn wenig Zeit
- Option 7 wenn schon Projekt-Idee

### Problem 4: "Darf ich KI für mein Projekt verwenden?"
**Lösung:**
- Ja, ausdrücklich erlaubt!
- Aber: Verständnis muss da sein
- Code muss erklärt werden können
- In Dokumentation erwähnen

## Bewertung des Vorbereitungsauftrags

### Option A: Pass/Fail
- **Pass:** Mindestens 1 Option oder 2 Quick-Aufgaben gemacht + Reflexionsfragen beantwortet
- **Fail:** Nichts abgegeben oder unvollständig

### Option B: Punkte (falls Teil der Bewertung)
- **3 Punkte:** Vollständig, kritisch reflektiert, gute Beispiele
- **2 Punkte:** Vollständig aber oberflächlich
- **1 Punkt:** Unvollständig aber Versuch erkennbar
- **0 Punkte:** Nicht abgegeben

### Option C: Keine Bewertung
- Freiwillig als Vorbereitung
- Aber: Diskussion in L09 setzt Teilnahme voraus

## Rechtliche Hinweise

**Wichtig für Studierende kommunizieren:**

✅ **Erlaubt:**
- KI für Lernzwecke nutzen
- KI für Code-Erklärungen
- KI für Optimierungsvorschläge
- KI als "Gummienten-Debugging"

⚠️ **Mit Vorsicht:**
- KI-generierten Code blind übernehmen
- Ohne Verständnis abgeben
- Nicht als Quelle angeben

❌ **Nicht erlaubt:**
- Code als eigenen ausgeben ohne zu verstehen
- In Prüfungen (außer explizit erlaubt)
- Für andere Studierende Code generieren lassen

## Beispiel-Abgaben

### Gute Abgabe - Option 1:

```markdown
# Meine KI-Erfahrungen

## Tool: ChatGPT Free

### Aufgabe 1: SQL Query generieren
**Prompt:** "Erstelle SQL Query für Bücher mit >3 Ausleihen"

**Antwort:** [Code hier]

**Bewertung:** ⭐⭐⭐⭐ (4/5)
- Query funktioniert
- Gute Erklärung
- Aber: Hatte Fehler bei JOIN Syntax

### Aufgabe 2: Code Review
[...]

## Reflexion
- KI war sehr hilfreich für Einstieg
- Aber: Muss Code immer selbst prüfen
- Würde für einfache Tasks wieder nutzen
```

### Mittelmäßige Abgabe:

```markdown
Ich habe ChatGPT getestet.
Es hat mir SQL Code gegeben.
War okay.
```
→ Zu oberflächlich, keine kritische Reflexion

### Schlechte Abgabe:

```markdown
[Nur Screenshots ohne Kommentar]
```
→ Keine Reflexion, kein Lerneffekt erkennbar
