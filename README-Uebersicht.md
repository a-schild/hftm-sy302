## Wichtige Hinweise

### Einheitlichkeit

**Code-Beispiele:**
- ✅ Alle Code-Beispiele sind auf **Englisch** (identisch in DE & FR)
- ✅ SQL-Befehle sind identisch
- ✅ Tabellennamen: `customers`, `orders`, `books`, `authors`

**Erklärungstexte:**
- ✅ Deutsche Erklärungen in DE-Dateien
- ✅ Französische Erklärungen in FR-Dateien

**Struktur:**
- ✅ Jede Lektion hat die gleiche Struktur
- ✅ Lernziele, Theorie, Beispiele, Übungen, Ressourcen
- ✅ DE- und FR-Fassung einer Lektion sind inhaltlich identisch (gleiche Abschnitte in gleicher Reihenfolge, gleiche Codeblöcke). Änderungen immer in beiden Sprachen nachführen.

### PDF-Handouts erzeugen

Die Markdown-Dateien sind die Quelle. Die PDFs werden mit der HFTM-Vorlage
`Vorlage/Vorlage_KleineDokumente.dotx` erzeugt (Kopfzeile Kurs/Autor/Version, Logo,
Fusszeile Dateiname/Seite/Datum). Word-Dokumente werden nicht mehr gepflegt.

```powershell
python tools/build-exports.py                               # Lektion 01-13, Checklisten, Uebungen
python tools/build-exports.py "Lektion 08/Lektion08-REST-API.md"   # einzelne Datei
```

Voraussetzungen: pandoc, Microsoft Word (Windows). Das Skript setzt «schlaue»
Seitenumbrüche: Überschriften bleiben beim folgenden Inhalt, Codeblöcke, kurze
Listen (Checklisten-Abschnitte) und kurze Tabellen werden nicht getrennt, Tabellen-
zeilen nie geteilt, der Tabellenkopf wird auf jeder Seite wiederholt.

### Beispieldatenbank

**HFTM Library** wird durchgehend verwendet:
- `books` (id, title, author_id, publisher_id, isbn, published_date)
- `authors` (id, firstname, lastname, email, birth_date)
- `publishers` (id, name, address, email)
- `genres` (id, genre)
- `customers` (id, firstname, lastname, email, location_id)
- `places` (id, zip, city)
- `lends` (id, customer_id, book_id, date_from, date_to, price)

## Kursplanung (13 Units)

| Unit | Thema | Specials |
|------|-------|----------|
| 1 | Daten / Datenbanken / DBMS | Credit 1 |
| 2 | Datenbankdesign, SQL DDL | Credit 2 |
| 3 | SQL DML | Credit 3, Raspberry Pi: MariaDB installieren |
| 4 | SQL JOIN / UNION | Credit 4, Raspberry Pi: HeidiSQL über SSH-Tunnel |
| 5 | SQL DCL / TCL | Credit 5, Raspberry Pi: MariaDB im Netzwerk freigeben (0.0.0.0) |
| 6 | SQL-Repetition | Projektstart |
| 7 | Theorieprüfung SQL / Node.js + DB | Theorieprüfung SQL, Credit 6, Raspberry Pi: Node.js Hello World |
| 8 | REST API | Abgabe DB-Design, Credit 7 |
| 9 | KI / AI, Projektarbeit | Credit 8 |
| 10 | NoSQL & MongoDB | Credit 9 |
| 11 | Express / REST API / ORM | Credit 10 |
| 12 | MQTT, Sicherheit | Abgabe Projekt auf GitLab (nach Unit 12) |
| 13 | Datenschutz, Backups, Kursabschluss | Präsentation Projekt, Buffet (optional): MongoDB auf dem Raspberry Pi |

Die Theorieprüfung ist erst in Unit 7, weil in den Units 3–7 zusätzlich Übungen auf dem Raspberry Pi stattfinden.
Die konkreten Daten stehen in der Kursplanung auf Moodle (der Kurs wird jährlich durchgeführt).

**Credits:** Jeder Credit wird mit 0–5 Punkten bewertet; eine fristgerechte, vollständige Abgabe gibt 5 Punkte, eine nicht abgegebene 0 Punkte, eine verspätete höchstens 5 Punkte. Die Punkteraster in `Uebungen/` sind interne Bewertungsraster und werden auf 0–5 Punkte skaliert.
